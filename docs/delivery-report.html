What was delivered

A multi-tenant consulting workspace that answers only from a customer's approved documents, reviews those documents against regulations, and produces corrected editions — with every claim traceable to a quotation that can be re-located in the stored source text.

The product's central property is mechanical rather than aspirational: a quotation is looked up, never generated. Every excerpt is searched for in the stored page text before its citation is persisted, so the system cannot show a quote that is not in the document. The default answering engine is deterministic and extractive — it selects sentences from retrieved passages rather than writing prose — which means it needs no credentials and cannot hallucinate. Anthropic and OpenAI plug into the same interface and pass the identical verification gate.

Recommended next

Five features, each grounded in something observed while building and testing this system rather than in what a compliance product usually has.

  1. 01

    Regulation version tracking with impact analysis

    When a new edition of a regulation lands, diff its clauses and raise a re-review queue naming every past finding whose citation points at text that has since changed.

    Evidence Versions, checksums and citation-to-version pinning already exist, and an old citation still resolves after a reprocess. The gap it closes is invisible today: a citation into a superseded clause still verifies, because the text really was on that page in that edition.

  2. 02

    Evidence review queue with reviewer sign-off

    Route low-confidence and needs-evidence findings to a Reviewer who can confirm, override with a reason, or request more evidence — with the override joining the audit trail and the report.

    Evidence The Reviewer role and review:approve exist with no workflow behind them. The correction path is review-first; the finding path is not. It also produces the labelled data every other quality improvement would need.

  3. 03

    Cross-document conflict detection across the corpus

    A scheduled pass comparing requirements across sources, surfacing where a local code, a client standard and an international standard disagree — with both citations and a precedence recommendation.

    Evidence detectConflict already finds contradictions and already declines to fire on unrelated quantities. It has simply never been pointed at the corpus as a whole, only at one answer's evidence set.

  4. 04

    Bilingual evidence with clause-aligned Japanese

    Per-source language detection and stored clause alignment between a regulation and its official translation, so a citation displays in the reader's language while still verifying against the authoritative original.

    Evidence The i18n structure and the Japanese OCR packs are already in place, but every evidence path assumes one language per source. Translating at display time cannot work — verification must run against the authoritative text, so the aligned pair has to be stored.

  5. 05

    Retrieval telemetry with a feedback loop

    Persist the retrieval trace per answer — expanded query, per-channel candidates, fusion and rerank signals — joined to the thumbs-up/down already collected, and an offline harness that replays the worst clusters against a config change.

    Evidence The metrics and the feedback both exist and are never joined. Every retrieval threshold today is measured against a five-case gold set built by hand: enough to catch a regression, not enough to guide an improvement. Highest ratio of insight to effort on this list.

Running it

# Everything the app needs, on one machine
docker compose -f infra/docker-compose.yml up -d
pnpm install && pnpm db:migrate && pnpm db:seed
pnpm dev

# The gate: format, lint, types, every Vitest project, production build
pnpm verify

# Browser layers, against a running stack
pnpm test:e2e     # 49 tests at three viewports
pnpm test:a11y    # 37 axe and keyboard-only tests

The seed ingests real documents through the real worker and runs a real compliance review, so the dashboard is populated on first sign-in rather than empty. It prints the address and password to sign in with.

Full documentation is in docs/: architecture with data-flow diagrams, threat model, data retention, RAG evaluation, operations runbook, deployment, acceptance scenarios, and the complete verification log this report summarises.
